## How the rings work, and how a new quest gets one (notes for future agents)

- The game already draws a ring for the quest picked in the Quests page (key J, row id `qrow_<id>`, handler `questShow`) through `questSpots()` and `drawQuestRings()` (index.html), which `mpplDraw` (maps_play.js) and the Khemetra map call on every area map. On another level `questShow` opens the world map (`G.qFocus.loc`, ring drawn in drawWorldMap) or, when a chain of doors leads there, rings the door on the local map.
- The game only knew a giver or, for a few quests, a `QUESTS.<id>.spot()`. `src/desert/quest_rings_fix.js` (last in tools/inject.py ORDER) adds a table `QRF.T.<questId> = {give:[spec], act:[spec], ready:[spec]}` and wraps `questSpots`, `questTargetLevel`, `questWorldLoc`, `questShow` and `drawWorldMap`. `ready` defaults to `give`, `give` defaults to `act`.
- A spec is `N(level,"npcId",...)` (people and things by decor id), `E(level,/type/)` (every live creature of that type), `I(level,"itemId")` (things on the ground), `K(level,"kind")`, `X(level,x,y)`, `CH(level,"X")` (exit squares) or `F(level,fn)` (a function returning [{x,y}]). Add `via:{<level>:[x,y]}` when the way in is not a normal door. `act` may be a function when the target changes with the quest step (see the graveyard quests).
- To give a new quest a ring: add one line to QRF.T, run `python tools/inject.py`, add the id to tools/qrings/main_ids.json, run `python tools/qrings/run2.py tools/qrings/results_after.json <id>` and `python tools/qrings/analyze.py tools/qrings/results_after.json`. If the target only exists after a story event, put a JS snippet that sets the state in tools/qrings/flags.json.
- The panel only lists quests the party has taken, so the "not taken" stage is checked through `questShow` directly (the same function the panel calls). Done quests show no ring and a note "is done".
- Harness files: qlib.py (browser), qr_page.js (injected helpers and canvas hooks), run2.py (all stages), doors.py (walk the doors step by step), lifecycle.py (ring goes when done or when the map is left), shots.py (screenshots), analyze.py, make_report.py, meta.py, dump_data.py (levels, people, doors to JSON).
- Known: the Exsce map (level 481, hgt_town_exsce.js `exmDraw`) throws when opened (EXTINT has no entry for some wall type) and froze the game; quest_rings_fix.js now catches a throwing level map and draws a plain map of the level with the rings and a Close button, and a separate task was opened to fix `exmDraw` itself. In the Khemetra sea tunnel (level 266) the ring target is reached through a teleporter.
